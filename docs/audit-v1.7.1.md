# v1.7.1 추가 최적화

2026-10-30, v1.7.0 (`97a9f75`) 이후 남아 있는 비용을 측정했습니다.

## 변경

- **P2 읽기**: 픽셀마다 임시 문자열을 만들던 방식을 직접 정수 파싱으로 바꾸고, 이미지 행
  포인터를 재사용합니다. 주석·공백·선행 0, 정수 오버플로와 잘못된 입력 검사는 유지합니다.
- **픽셀 실행 취소**: 변경 전·후 영역 두 개 대신 가역적인 XOR 변경분 하나만 압축합니다.
  같은 변경분을 적용해 실행 취소·다시 실행할 수 있으며 이미지 파일 형식에는 영향이 없습니다.
  회전·자르기 기록은 기존 방식을 유지합니다.
- **마스크 읽기**: trinary 마스크의 점유 판정을 256단계 조회표로 바꾸고, 변환 결과가 이미
  0·100·255임이 보장되는 경우 추가 전체 검사를 생략합니다. raw 값 검사는 유지합니다.
- **포인터 이동**: 그리지 않을 때에는 이전·새 펜 커서 주변만 다시 그립니다. 이동 도구처럼
  화면이 변하지 않는 경우에는 좌표 안내만 갱신합니다. 그리기·이동·좌표 작업 처리는 유지합니다.

## 측정

Intel Core i7-14700HX, Linux x86_64, Qt 6.4.2, CMake Release 빌드입니다. P/E 코어 배치 차이를
줄이기 위해 두 실행 파일을 CPU 0에 고정하고 이전·새 버전을 번갈아 세 번 실행했습니다.
실행 내부의 반복 측정과 세 실행 결과 모두 중앙값을 사용했습니다. 파일 읽기는 준비한 파일의
웜 캐시 기준이며 작업 스레드 전달 비용을 제외한 코어 처리 시간입니다.

| 작업 | v1.7.0 | v1.7.1 |
| --- | ---: | ---: |
| 4096×2048 P2 읽기·디코딩 (변경 감지용 SHA-256 계산 제외) | 359.11ms | 75.53ms |
| 2048×1024 무작위 이미지의 편집 기록 생성·취소 | 77.08ms | 44.47ms |
| 위 이미지 전체를 바꾸는 편집 명령 1개의 압축 데이터 | 4,195,604B | 2,097,802B |
| 4096×2048 trinary 마스크 읽기·변환 | 80.40ms | 58.83ms |
| 32 Mi 픽셀 지도와 두 마스크 위에서 펜 포인터 이동 100회 | 424.24ms | 1.33ms |
| 같은 화면에서 이동 도구의 포인터 이동 100회 | 412.85ms | 0.10ms |

포인터 항목은 각 입력 후 이벤트 처리를 수행해 실제 다시 그리기 비용을 포함했습니다.
새 버전은 변경한 작은 영역만 그리거나 다시 그리기를 생략하므로, 이를 전체 화면 렌더링이
수백 배 빨라졌다고 해석하면 안 됩니다. 두 마스크를 포함한 전체 화면 다시 그리기는 같은
측정에서 약 4~8ms로 이전과 비슷합니다.

기록 용량의 절반 감소는 이전·새 이미지가 모두 무작위 값인 해당 시나리오의 결과입니다.
앱 전체 메모리가 절반으로 줄었다는 의미는 아니며 지도 내용에 따라 차이가 있습니다.
8 Mi 픽셀의 규칙적인 편집은 32.95→29.69ms로 개선 폭이 작았습니다. 마스크를 겹쳐 그리는
부분은 이미 빠른 편이므로 렌더링 구조를 변경하지 않았습니다.

## 검증

- 기존 파일·좌표·마스크·번역·작업 스레드 회귀 테스트 유지.
- P2 주석·여러 공백·선행 0, 음수·부호·잘못된 문자·정수 오버플로 검사.
- 홀수 이미지 너비의 희소 편집을 여러 번 취소·다시 실행하고 자르기·새 분기와 혼합해 픽셀 일치 검사.
- 2 MiB 무작위 편집 50개 후 횟수 한도 40개 유지, 실행 취소 후 분기 기록 검사.
- negate 0·1과 두 마스크 종류에서 256개 픽셀값을 직접 점유 확률 판정과 대조.
- 펜 포인터의 실제 다시 그리기 영역과 이동 도구의 불필요한 다시 그리기 생략 검사.

로컬 Qt 테스트 4개 묶음과 Python 검사 8개를 통과했습니다. AddressSanitizer/UBSan 빌드에서도
같은 Qt 검사를 통과했습니다. `ASAN_OPTIONS=detect_leaks=0`이며 누수 검사는 포함하지 않았습니다.

기존 32 Mi 픽셀·레이어별 기록 40개/96 MiB 제한, 파일 저장 잠금·해시·백업 정책과
재사용하는 단일 작업 스레드 구조를 유지합니다. 추가 라이브러리는 필요하지 않습니다.
