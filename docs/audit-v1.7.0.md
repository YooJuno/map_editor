# v1.7.0 성능·안정성 점검

2026-10-29, v1.6.1 (`fa5793b`)과 비교했습니다.
파일 입출력, 그리기, 실행 취소, 마스크와 좌표 편집 정책, 작업 중 이벤트 처리를 점검했습니다.

## 발견한 문제와 수정

| 문제 | 수정 |
| --- | --- |
| 읽기·저장·회전·채우기·기록 압축이 GUI 스레드를 오래 점유 | 전용 작업 스레드 하나에서 순서대로 처리. 스레드를 재사용하고 60초 유휴 시 해제 |
| 작업 중 이벤트를 처리하면 중복 저장·편집·닫기 등이 끼어들 수 있음 | 작업 전체 구간에 편집 잠금과 진입 검사를 적용. 창 다시 그리기·이동·확대는 허용 |
| 작은 획도 전체 지도와 비교 | 실제 변경 후보 영역만 비교하고 압축 |
| 직선·사각형·다각형 미리보기에서 지도 복사와 중간 입력 처리가 반복 | 그리기 버퍼와 변경 영역을 재사용. 포인터 이동은 16ms마다 최신 입력을 반영하고 완료 시 마지막 입력을 즉시 반영 |
| 굵은 펜에서 원형 스탬프의 겹친 영역을 계속 덧칠 | 굵기별 스캔라인 범위를 캐시하고 겹친 구간을 합쳐 기록. 기존 픽셀 모양 유지 |
| 변환·여백 검색에서 같은 확률 계산 반복 | 256단계 조회표와 행 단위 순회 사용 |
| 회전 직후 이미 만든 결과를 압축 해제해 다시 생성 | 최초 적용에는 완성된 이미지를 바로 사용하고 이후 실행 취소·다시 실행에 압축 기록 사용 |
| 로드 후 파일을 다시 읽어 해시를 잡아 그 사이 외부 변경을 놓칠 수 있음 | 실제 파싱·디코딩한 바이트의 SHA-256을 문서와 함께 보관 |
| 여러 실행 인스턴스의 저장 충돌 | YAML과 PGM 각각에 정렬된 경로 순서로 저장 잠금 획득. 잠금 안에서 외부 변경 검사 |
| 저장·실패 복구 시 큰 파일을 통째로 추가 복사 | PGM 기록·해시와 복구를 256 KiB 블록으로 처리. 저장 직후 해시 재독출 제거 |
| 특수 파일 입력으로 읽기가 끝나지 않거나 읽기 중 커진 파일이 제한을 넘을 수 있음 | 일반 파일만 읽고, 파일 크기 사전 검사 외에 실제 읽기량도 제한 |
| 횟수 제한으로 사라진 기록과 버린 다시 실행 기록이 메모리 계산에 남음 | 현재 보유하는 기록만 계산해 불필요한 전체 기록 초기화 방지 |
| 회전·자르기 실패 전에 저장된 마스크 표시가 닫힘 | 좌표 변경이 성공한 뒤에만 표시 해제 |
| 원점 미리보기가 탭 이동만으로 확정됨 | 다른 좌표 작업과 동일하게 탭 이동 시 취소. 적용·Enter·저장으로 확정 |
| 마스크 표시를 끄면 그리던 다각형이 자동 확정됨 | 표시 변경과 확정을 분리하고 숨긴 상태에서도 완료·취소 가능 |
| 작업 스레드 예외와 일부 메모리 오류의 UI 전달 부족 | 원본 예외를 GUI로 돌려 안내. 작업 상태 복구, 이미지 할당·기록 복원 오류 검사 |

작업 함수는 이미지·메타데이터의 값 복사만 받고, 문서와 실행 취소 스택 변경은 GUI 스레드에서
수행합니다. 컨트롤러는 완료 결과를 기다리는 동안 보호된 이벤트 루프를 돌려 기존 저장·닫기
처리 순서를 유지합니다. 여러 편집을 동시에 수행하거나 저장을 중간에 취소하지 않습니다.
120ms 이상 걸리는 작업만 상태 표시줄에 진행 표시를 보여 줍니다.

별도 작업 프로세스는 생성하지 않습니다. 기존 실행 스크립트도 `exec`로 앱에 제어를 넘깁니다.
추가 런타임은 Qt Concurrent 모듈이며 브라우저·Python·ROS·네트워크 서비스는 사용하지 않습니다.
그리기 임시 버퍼는 레이어·좌표 작업 전환 또는 30초 유휴 후 해제합니다.

## 같은 장비에서 측정한 결과

Intel Core i7-14700HX, Linux x86_64, Qt 6.4.2, CMake Release 빌드를 사용했습니다.
같은 벤치마크를 각각 세 번 실행한 중앙값입니다. 편집·변환·펜 항목은 실행 내부에서도 세 번
측정했습니다. 작업 스레드 전달 비용을 제외한 코어 처리 시간이며 디스크·GPU·실제 지도 내용에
따라 결과는 달라집니다. 지도는 기본 회색으로 채웠고, 작은 편집은 검정 64×64 영역입니다.

| 작업 | v1.6.1 | v1.7.0 | 비교 |
| --- | ---: | ---: | ---: |
| 8192×4096 지도에서 64×64 편집 기록 생성 및 취소 | 3.164ms | 0.097ms | 약 33배 |
| 8192×4096 지도 3색 변환 | 185.99ms | 36.65ms | 약 5.1배 |
| 4096×4096 지도에서 굵기 256의 긴 대각선 획 | 12.30ms | 2.78ms | 약 4.4배 |
| 4096×4096 지도 12° 회전 및 기록 생성 | 417.63ms | 259.64ms | 약 1.6배 |
| 위 시나리오 전체의 프로세스 최대 RSS | 217.2MiB | 195.5MiB | 약 10% 감소 |

32 Mi 픽셀 지도에서 사각형 포인터 이동 이벤트 100회를 연속으로 보내면 이전 버전은
1,316.5ms를 사용했습니다. 새 버전은 최신 입력을 모아 다음 미리보기 주기에 반영하며 이벤트
접수에는 0.038ms, 마지막 입력 확정에는 0.223ms를 사용했습니다. 이전 확정 시간은 17.915ms입니다.
중간 프레임 100장을 모두 그린 비교가 아니므로 이를 렌더링 속도 수천 배 향상으로 해석하면
안 됩니다. 마지막 픽셀 결과와 취소 후 잔상 여부는 별도 회귀 테스트로 검증했습니다.

최대 RSS는 여러 지도·복사본을 순서대로 사용하는 이 벤치마크 프로세스의 수치이며 앱의
평상시 메모리 사용량을 뜻하지 않습니다. 빠른 연속 그리기를 위해 활성 그리기 버퍼를 잠시
보관하므로 모든 상황에서 메모리가 줄어드는 것은 아닙니다.

## 검증

- Qt 기능·마스크·번역·안정성 테스트 4개 묶음 통과.
- 번역 누락·치환 인자, 배포 버전·경로, 압축 파일·실행 권한 등 Python 검사 8개 통과.
- AddressSanitizer/UndefinedBehaviorSanitizer 빌드에서 같은 Qt 테스트 통과.
  `ASAN_OPTIONS=detect_leaks=0`으로 실행했으며 누수 검사는 포함하지 않았습니다.
- 브러시의 픽셀 모양을 독립적인 정수 원 판정과 120개 무작위 획으로 비교.
- 외부 변경, 두 문서의 오래된 저장, 저장 잠금, 스트리밍 파일·해시 일치 검증.
- 기록 50개 생성·자동 삭제·실행 취소 후 분기 시 메모리 계산 검증.
- 작업 스레드 재사용, GUI 타이머 응답, 중복 진입·닫기·열기·그리기 차단,
  예외 후 정상 복구, 작업 중 언어 변경 검증.
- 실제 4096×4096 회전 중 화면 이벤트 처리와 결과 적용 전 원본 유지 검증.
- 최소 창 크기 1060×700에서 다크·라이트, 마스크·회전·자르기·원점·다각형,
  한국어·영어·일본어·중국어 작업 표시 화면 확인.

배포 빌드는 기존 GitHub Actions의 Ubuntu x64, Windows x64, macOS arm64·x64 매트릭스에서
Qt 6.8.3으로 별도 검사하며, 네 환경이 성공해야 Release를 발행합니다.

## 유지되는 제한

YAML과 PGM을 한 번에 원자적으로 교체할 수는 없습니다. 덮어쓰기 전 백업과 YAML 실패 시
PGM 복구를 제공하지만 전원 중단 시에는 `.mapwright-backups`에서 복원해야 합니다.
저장 잠금은 Map Editor끼리 협력하는 방식이며 잠금을 사용하지 않는 다른 프로그램의 동시
쓰기까지 막지는 않습니다. 백업은 자동 삭제하지 않습니다.

지도의 최대 크기는 32 Mi 픽셀입니다. 실행 취소는 각 레이어마다 최대 40개이며 보유 압축 기록이
96MiB를 넘으면 이전 기록을 비웁니다. 이 제한과 기존 지도·마스크 파일 형식은 유지했습니다.
